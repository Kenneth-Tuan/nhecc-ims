# NHECC IMS 第一階段開發時程規劃

本計畫涵蓋 **系統管理**、**裝備系統** 與 **牧養系統** 三大核心模組的開發時程。由於前兩者有明確的上線壓力，故將第一階段分為三個執行部分：

1.  **Part A：系統管理與裝備系統** (2025/12/11 - 2026/01/31) - **急迫**
2.  **Part B：緩衝與優化期** (2026/02/01 - 2026/02/14) - **Hotfix**
3.  **Part C：牧養系統** (2026/02/15 - 2026/04/11) - **8 週衝刺**

---

## Part A: 系統管理與裝備系統 (2025/12 - 2026/01)

### 核心目標

在 2026 年 1 月底前，完成 MVP 並交付給核心同工進行測試。

| 週次   | 日期          | 階段                | 重點工作項目                                                                                   | 產出里程碑                         |
| :----- | :------------ | :------------------ | :--------------------------------------------------------------------------------------------- | :--------------------------------- |
| **W1** | 12/11 - 12/17 | **定義 & 流程**     | 1. 確認 User Stories<br>2. **資料庫 Schema 定案** (含課程時間結構)<br>3. 確定權限矩陣          | DB Schema v1.0<br>API 規格文件     |
| **W2** | 12/18 - 12/24 | **原型 & 驗證**     | 1. Nuxt UI 高保真 Mockup (無後端)<br>2. **內部快速驗證**：確認報名/點名流程                    | 可互動 UI Prototype                |
| **W3** | 12/25 - 12/31 | **開發 (Sprint 1)** | **系統管理核心**<br>1. LINE 登入 / JWT 驗證<br>2. 角色權限 (RBAC)<br>3. 使用者管理 (CRUD)      | 管理員可登入<br>可建立使用者       |
| **W4** | 01/01 - 01/07 | **開發 (Sprint 2)** | **裝備系統 - 課程管理**<br>1. 課程開設/編輯 (CRUD)<br>2. 前台課程列表與搜尋<br>3. 報名邏輯實作 | 管理員可開課<br>學員可報名         |
| **W5** | 01/08 - 01/14 | **開發 (Sprint 3)** | **裝備系統 - 課堂互動**<br>1. 我的課程 (分眾視角)<br>2. 請假申請與審核<br>3. QR Code 點名機制  | 完整上課流程<br>(報名->點名->請假) |
| **W6** | 01/15 - 01/21 | **開發 (Sprint 4)** | **收尾與優化**<br>1. 系統審核作業 (Audit Logs)<br>2. 處理 Token/圖片上傳<br>3. 安全性檢查      | Feature Complete MVP               |
| **W7** | 01/22 - 01/31 | **交付 & 部署**     | 1. 部署 Production 環境<br>2. 建立種子資料<br>3. **Key User 測試啟動會**                       | **系統上線 (Beta)**<br>使用者手冊  |

---

## Part B: 緩衝與優化期 (2026/02/01 - 2026/02/14)

### 核心目標

針對 Part A 上線後收集到的 Key User 回饋進行快速修正，並穩定系統運作，同時為牧養系統做準備。

| 週次          | 日期          | 重點工作項目                                                                                                                                     |
| :------------ | :------------ | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Buffer W1** | 02/01 - 02/07 | **Hotfix 與 效能監控**<br>1. 修復 Key User 回報的 Critical/Major Bugs<br>2. 監控伺服器負載與資料庫效能<br>3. 優化 UI 操作流暢度 (根據回饋)       |
| **Buffer W2** | 02/08 - 02/14 | **檢討與準備**<br>1. 盤點 Part A 遺留的技術債 (Technical Debt)<br>2. **啟動牧養系統 Persona Survey** (提前準備)<br>3. 確定 Part C 的詳細需求範疇 |

---

## Part C: 牧養系統 (2026/02/15 - 2026/04/11)

### 核心目標

在 **8 週** 內完成具備隱私保護與小組架構管理的牧養系統。
