# Tranning System

## 使用者

1. 全體

## 詳細功能

1. 新增/編輯課程

   1. 課程 id（系統自動產生）
   2. 課程名稱
   3. 課程編號
   4. 課程狀態（發佈/結業/進行中）
   5. 課程縮略圖
   6. 先修條件（String Array；選擇課程編號）
   7. 開課地點
   8. 上課時間（Object Array；可能每週有多天要上課，可能某天有多個上課時段，也可能兩週上一次、一個月上一次、兩個月上一次，要如何設計這裡的資料結構？）
   9. 開課日期
   10. 結課日期
   11. 授課老師（teacher id）
   12. 上課方式（實體 or 線上）
   13. 選課人數上限
   14. 課程簡介（rich text）
   15. 課程大綱（File Array？）

2. 所有課程（默認顯示已發佈的課程）

   1. 點擊後進入詳細課程畫面
   2. 詳細課程畫面的 bottom 為報名按鈕（狀態為進行中&結業則無此區塊）
   3. 頁面佈局從上至下依次為：banner，課程資訊（開課時間、時長、學員、授課老師），課程簡介，課程大綱，關於講師（User Avatar）
   4. 列表（UI：card list）；顯示縮略圖 + 名稱 + 簡介；依照課程類型，名稱，狀態，開課時間進行搜尋；依照時間排序

3. 我的課程（默認顯示進行中的課程；manager，pastor 可瀏覽全部進行中的課程，其餘角色只能瀏覽與自己相關的）

   1. 列表（同所有課程）；額外區分老師/學生
   2. 單一課程
      1. 公告
      2. 作業
      3. 成績
      4. 教材
      5. 出勤紀錄

4. 請假申請
   1. 申請人名稱（系統自帶）
   2. 申請人 id（系統自帶）
   3. 請假課程（課程 id）
   4. 請假類型（病假/事假/公假）
   5. 請假日期
   6. 請假原因
   7. 附件
5. 申請紀錄
   1. 一般用戶可以看到自己的申請紀錄
   2. 老師可以看到自己&授過課程的學生的請假紀錄
   3. creator，poster，manager 可以看到所有的請假紀錄
   4. 小組長、區長、長老、辦公室同工，這些角色的權限是否有默認設定？
6. 課程公告
   1. 新增/編輯/刪除公告（rich text）
   2. 新增/編輯之後，通知學生（編輯之後是否也需要進行通知？）
7. 課程報名
   1. 流程請參考 2.2
   2. 是否要檢查時間衝突？
   3. 今後是否會需要繳費？
8. 課程點名/簽到
   1. 我的課程中，如果為授課老師，則會有一個點名按鈕
   2. 點擊之後跳出 popup 確認要點名的節次
   3. 確認完畢之後點擊產生 qrcode
   4. 學生掃描 qrcode 會自動訪問系統簽到頁面，如未登入則執行登入流程
   5. 自動 post 簽到資訊之後，簽到頁面顯示簽到成功、學生姓名、課程名稱、節次
