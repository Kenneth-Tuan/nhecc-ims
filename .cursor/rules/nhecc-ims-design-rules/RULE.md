# NHECC 系統設計規範 (Design System Spec) v1.0

## 1. 核心設計理念 (Design Philosophy)

- **視覺風格**：**Soft Card UI (柔和卡片風格)**。
  - 參考您提供的圖片，我們採用「大圓角白色卡片」懸浮於「淺色背景」之上的設計。
  - 利用柔和的擴散陰影 (Diffused Shadows) 取代生硬的邊框，營造空氣感與現代感。
- **體驗原則**：**PWA Native-Like (類原生 App 體驗)**。
  - 針對手機操作優化，核心交互區域位於螢幕下半部 (Thumb Zone)。
  - 字體級距大，對比度高，確保 85 歲長者閱讀無礙。

## 2. 視覺系統 (Visual System)

### 2.1 色彩計畫 (Color Palette)

基於您定義的 OKLCH 色碼，我們將其映射到 UI 功能語意：

| 變數名稱       | 色碼 (OKLCH)            | 功能語意        | 應用場景                           |
| :------------- | :---------------------- | :-------------- | :--------------------------------- |
| **Primary**    | `--color-nhecc-red-500` | **核心行動**    | 主要按鈕 (CTA)、選中狀態、關鍵圖標 |
| **Surface**    | `--color-nhecc-red-50`  | **背景底色**    | PWA 全域背景色 (非常淺的暖調)      |
| **Success**    | `--color-nhecc-green`   | **成功/進行中** | 簽到成功、審核通過、課程進行中     |
| **Warning**    | `--color-nhecc-yellow`  | **待辦/審核中** | 待繳作業、請假審核中、遲到         |
| **Info**       | `--color-nhecc-teal`    | **資訊/連結**   | 課程標籤、非破壞性提示             |
| **Accent**     | `--color-nhecc-purple`  | **特殊/裝飾**   | 講師頭像邊框、插畫點綴             |
| **Text-Dark**  | `#1F2937` (Gray-900)    | **主要文字**    | 標題、正文 (**禁用純黑 #000**)     |
| **Text-Light** | `#6B7280` (Gray-500)    | **次要文字**    | 日期、輔助說明                     |

### 2.2 字體系統 (Typography)

- **Font Family**: System UI (iOS: San Francisco / Android: Roboto / Web: Inter)
- **Base Size**: `16px` (瀏覽器預設)，**內文絕不小於 16px**。
- **Scale**:
  - `H1 (頁面標題)`: 24px / Bold / Line-height 1.3
  - `H2 (卡片標題)`: 20px / Semi-Bold / Line-height 1.4
  - `H3 (強調資訊)`: 18px / Medium / Primary Color
  - `Body (內文)`: 16px / Regular / Line-height 1.6 (**老人友善行高**)
  - `Caption (標籤/輔助)`: 14px / Regular / Gray-500 (**最小尺寸**)

### 2.3 卡片與陰影 (Cards & Shadows)

這是本專案的視覺靈魂（參考 Ref Image 1 & 2）。

- **Card Container**:
  - Background: `#FFFFFF`
  - Border Radius: `20px` (大圓角)
  - Padding: `20px` (內部留白要大)
  - Shadow: `0px 10px 40px -10px rgba(0,0,0,0.08)` (大範圍柔和陰影)

## 3. UI 元件規範 (Component Specs)

### 3.1 按鈕 (Buttons)

- **Primary Button (主要操作)**:
  - 背景: `--color-nhecc-red-500`
  - 文字: White
  - 高度: `56px` (極大觸控區)
  - 圓角: `16px`
  - 寬度: 100% (手機版)
- **Secondary Button (次要操作)**:
  - 背景: `--color-nhecc-red-100`
  - 文字: `--color-nhecc-red-700`

### 3.2 表單輸入 (Inputs) - _針對會友資料/請假_

- **樣式**: 灰色淡背景 (`#F3F4F6`) + 無邊框 (Focus 時出現 Primary 邊框)。
- **高度**: `52px` (避免點不到)。
- **Label**: 必須顯示在輸入框上方 (Outside Label)，不要只用 Placeholder。

### 3.3 底部導航 (Bottom Tab Bar)

- 固定於底部，高度 `64px` + Safe Area。
- **項目建議**:
  1.  **首頁 (Dashboard)**: 顯示今日課程、公告。
  2.  **課程 (Training)**: 找課、報名。
  3.  **我的 (My Learning)**: 作業、成績、請假。
  4.  **帳戶 (Profile)**: 個人資料、QR Code。

## 4. 關鍵功能畫面佈局 (Key Flows)

### 4.1 課程列表與詳情 (Training System)

- **列表頁 (Card List)**:
  - 每一堂課為一張「橫式卡片」。
  - 左側: 課程縮圖 (圓角矩形)。
  - 右側: 標題、講師頭像(小)、狀態標籤 (Pill Tag)。
  - 底部: 開課日期 (icon + text)。
- **詳情頁 (Course Detail)**:
  - **Banner**: 頂部大圖 (16:9)。
  - **Float Card**: 課程資訊（時間、地點、講師）做成一張懸浮卡片壓在 Banner 下緣。
  - **Tabs**: 切換「簡介 | 大綱 | 講師」。
  - **Bottom Action Bar**: 固定底部的「立即報名」按鈕。

### 4.2 點名/簽到流程 (Attendance)

- **老師端 (Mobile)**:
  1.  點擊「產生簽到碼」。
  2.  **全螢幕 Modal** 顯示超大 QR Code (高對比黑白)，下方顯示「倒數計時」或「動態重整」按鈕。
- **學生端 (Mobile)**:
  1.  掃描後開啟 PWA 頁面。
  2.  **回饋畫面**: 參考 Ref Image 2 的插畫風格。
      - **成功**: 綠色勾勾動畫 + 「簽到成功」大字 + 課程名稱。
      - **失敗**: 紅色驚嘆號 + 「非簽到時間」或「距離過遠」。

### 4.3 會友架構管理 (Member Tree) - _後台/平板功能_

- 這是一個複雜功能，建議在**桌面/平板**端操作。
- **UI 模式**: 左側「未分組池 (Unassigned Pool)」，右側「組織樹狀圖 (Org Chart)」。
- **操作**: 使用拖放 (Drag & Drop) 將左側人員拖入右側小組框框內。
- **審核標記**: 修改後，該節點變為黃色虛線框，標示「待審核狀態」。

# Remarks

## 全局設計原則

- 跨年齡易懂：12 歲能看懂怎麼上課、85 歲也找得到點名與請假入口；所有關鍵操作都必須搭配「文字說明＋清楚 icon」，絕不能只靠圖示或顏色判斷。
- 任務導向而非功能導向：畫面優先回答「我要上課／點名／請假／交作業／改作業」這些任務，而不是把所有功能塞進一個大選單。
- 一致性：按鈕樣式、顏色語意（成功／警告／錯誤）、表單排版、列表樣式在全站必須完全一致，避免不同頁面「叫法不同、呈現不同」讓使用者重新學習。

## 資訊架構與導航要求

- 依角色區分入口：設計稿需明確標示「學生／家長／老師／管理員」的主要任務入口，每個角色登入後的第一個畫面應是「今日我要做什麼」而不是功能列表。
- 導航層級不超過 3 層：例如「課程 → 某堂課 → 作業」，超過 3 層一定要設計麵包屑與明顯回上一層的按鈕，避免年長使用者迷路。
- 固定而簡單的主選單：主導航只保留極少數條目（例如：課程、點名/請假、作業、個人或孩子的學習概況），其餘進階功能放入「更多」或設定區，避免一開始就資訊轟炸。

## 版面、文字與互動細節

- 字級與對比：預設字級不得過小（內文最少 14–16px 等級），關鍵資訊（課程名稱、上課時間、繳交期限）必須有明確層級及足夠顏色對比，支援手機與桌機閱讀。
- 可點元素明顯可點：所有按鈕、連結、卡片要有清楚的「按鈕外觀」，避免用純文字假裝是按鈕；滑鼠 hover 或點擊時需有即時回饋。
- 表單與錯誤提示：請假、繳交作業等表單，錯誤訊息須貼近欄位、用自然語言解釋（例如「請選擇請假日期」而不是「欄位錯誤」），並避免用顏色當唯一提示。

## 關鍵情境（點名、請假、作業）的專屬要求

- 點名/簽到
- 老師端：設計稿需讓老師在一個畫面就能看到整班名單並快速勾選狀態（到／缺席／遲到），避免來回翻頁。
- 學生端：當天是否已簽到必須在首頁或課程卡片上就一眼看出來，避免重複操作或忘記。
- 請假流程
- 流程步驟最少化（理想狀況：選課程／日期 → 填原因 → 送出），每一步畫面都有清晰標題與目前步驟提示。
- 審核中、已核准、被退回的狀態需要在列表與細節頁有清楚標籤與說明，年長使用者一眼能看出結果。
- 作業繳交與批改
- 學生端：在「課程或作業列表」就要看到每一份作業的狀態（未繳／已繳／已批改）、截止時間以及是否逾期，避免要點進詳細頁才知道。
- 老師端：可以快速篩選「未批改／已批改／逾期繳交」，且在批改畫面中，學生基本資訊、作業內容與評分區塊需同屏可見，不要頻繁切頁。

## 儀表板與個人化需求

- 資訊量受控且可漸進展開：首頁儀表板只放「今天／本週要做什麼」與幾個最重要的指標，例如今日課程、待簽到、待繳交作業數量；進一步細節透過「查看全部」展開。
- 依角色客製摘要：
- 學生：近期課程、待繳作業、出缺席紀錄簡表。
- 老師：今日課表、待點名班級、待批改作業數量、異常情況提示（大量缺席等）。
- 避免用圖表取代文字：圖表可輔助趨勢，但重要資訊（例如缺席次數、平均成績）一定要有明確數字與標籤，以照顧視力較弱與不習慣閱讀圖表的年長者。

## 設計交付與規格說明

- 完整狀態設計：每一個關鍵畫面需提供「正常／Loading／空資料／錯誤／權限不足」等狀態設計，而不是只交付理想畫面。
- 互動與流程標註：在設計檔中使用註解或流程箭頭標明：按鈕點擊後去哪裡、有哪些彈窗、哪些為必填欄位、哪些會即時驗證。
- 元件庫與規則文件：提供清楚的設計系統（按鈕、表單、標籤、卡片、列表、表格、Tabs、步驟條等），並附上使用規則（例如「什麼情境用 Primary 按鈕／Danger 按鈕」、「錯誤訊息怎麼寫」），避免後續擴充時風格走樣。

## 手機 PWA 設計規範

1. 觸控與可達性 (Touch & Reachability)

- 拇指熱區原則：85 歲長輩的手指靈活度較低，所有關鍵操作（簽到、繳交）必須放在螢幕下半部 1/3 區域。左上角的「返回」按鈕對大螢幕手機非常不友善，建議搭配「右滑返回」手勢或在底部提供返回導航。
- 點擊目標尺寸：最小觸控區域需大於 44x44 px (或 48dp)。設計稿中緊湊的列表（如 Task List）若行距太密，長輩很容易誤觸上下行的項目。

2. PWA 專屬介面邏輯

- Safe Area (安全區域)：iPhone 的底部橫條 (Home Indicator) 和頂部瀏海區必須留白。設計稿的底部導航欄 (Tab Bar) 必須加上  padding-bottom ，避免按鈕被手機系統手勢條遮擋。
- 類 App 的導航架構：
  - 捨棄漢堡選單 (Hamburger Menu)：長輩不懂「三條線」是什麼。請使用底部標籤列 (Bottom Tab Bar)，清楚列出「課程、作業、聯絡簿、我的」。
  - Modals vs Pages：多用由下往上滑出的 Bottom Sheet (半版彈窗) 來處理「請假表單」或「點名詳細」，這樣使用者還能看到背後的脈絡，不會覺得「迷路了」。

1. 離線與系統狀態

- 網路不穩的焦慮感：PWA 可能在捷運或地下室使用。當網路斷線時，畫面不能變白屏。設計規範需包含**「離線模式 UI」**，明確告知：「目前離線，您的簽到將在連線後自動上傳」。
